# Fine

Fine is an experimental solver language built inside a soft fork of Z3. It is
not a frontend which sends constraints through a foreign solver API and then
prettifies the answer. Fine syntax and Z3 ASTs share one manager, with two exact
boundaries:

- `reify` maps Fine syntax to a Z3 term;
- `lift` maps a Z3 term into Fine's parseable generated core;
- for every supported live Z3 term, `reify(lift(x)) = x` by exact AST identity.

Rainfall exposes those boundaries while the solver runs. Compiler-owned source
correspondences, solver observations, generated terms, clauses, accepted
instances, models, and counterexamples remain separately identified instead of
being collapsed into a plausible proof story.

## A small program

```fine
enum Tm {
  atom,
  mark,
  wrap(body: Tm),
}

predicate Step(before: Tm, after: Tm) {
  constructor root() {
    takes {}
    gives Step(atom, mark);
  }

  constructor under(before: Tm, after: Tm) {
    takes { Step(before, after); }
    gives Step(wrap(before), wrap(after));
  }
}

check distinct(before: Tm, after: Tm) {
  inducts(Step(before, after));
  assumes { Step(before, after); }
  ensures { before == after == false; }
}
```

A `predicate` is specifically the smallest relation generated by its
`constructor` blocks, not an arbitrary named Boolean formula. `inducts` asks
Fine to construct one exact branch per retained constructor and one induction
hypothesis per recursive premise before Z3 checks the branch. Derivation
witnesses erase; Rainfall retains the branch evidence.

## Current executable surface

Fine currently has:

- finite model production and exact model-value round trips;
- typed counterexamples over integers, Booleans, enums, monomorphic recursive
  datatypes, and binary tuples;
- named reusable `proof` declarations admitted only after their negated query is
  unsatisfiable;
- recursive functions and compiler-owned constructor/direct-field induction;
- constructor-generated indexed predicates, least-relation membership and
  invariant checks, direct predicate-preservation induction, and erased
  constrained views;
- an editor-neutral Rainfall transaction protocol and a small loopback browser
  client which discards late solver runs after edits;
- an interruptible QF-LIA synthesis backend retained as a regression harness,
  not as the language's reason to exist.

This is a research compiler, not a stable verification tool. It does not yet
have general match expressions, projections, mutual recursion, parametric source
ADTs, runtime GADTs, proof-term values, existential predicate fields, or full
locally nameless STLC preservation.

## Build and run

The locked Nix build runs the executable integration suite:

```sh
out=$(nix build --no-link --print-out-paths)
"$out/bin/fine" run fine/fixtures/two-state-bisim.fine
"$out/bin/fine" run fine/fixtures/predicate-induction.fine
"$out/bin/fine" rain fine/fixtures/reusable-proof-induction.fine > trace.rain.jsonl
"$out/bin/fine-rain-validate" fine/fixtures/reusable-proof-induction.fine trace.rain.jsonl
```

For the native CMake build, fixture catalogue, and Rainfall utilities, see
[`fine/README.md`](fine/README.md). The governing semantic boundaries are in
[`fine/ARCHITECTURE.md`](fine/ARCHITECTURE.md), current work is in
[`TODO.md`](TODO.md), and the append-only experimental record—including failed
encodings and retained null results—is in [`LOG.md`](LOG.md).

## Z3 fork

Fine retains Z3's source and Git history because its observers and exact term
identity require changes below the public API. Z3 remains licensed under the
[MIT license](LICENSE.txt); its original build and project README is preserved as
[`README-Z3.md`](README-Z3.md). Fine's generic Z3 observer changes and its
language integration are kept conceptually separate even though this repository
builds them together.
